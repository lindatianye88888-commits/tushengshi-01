# 从需求到图纸的工作流规格

日期：2026-10-25。本文是完整工作流的目标规格；第一版已实现本地任务、检查、执行与四类基础图适配器，当前范围见 [README](../README.md) 和 [操作说明](../WORKFLOW.md)，未实现部分仍为建议设计。

已认可：50图归8组，并在8组上设置组级任务卡。当前结构为“项目共用信息 → 启用的组级任务卡 → 已选图纸的必要参数 → 汇总出图清单”。参见[八组任务卡](group-task-cards.md)与[机器可读定义](../catalog/group-task-cards.json)。具体字段和默认参数仍为设计草案。

## 1. 选图与描述共同更新同一份任务

用户可以直接选图、描述问题、指定图与参数，或交替进行。保留已有选择，不要求用户切换两种模式。分析目的可以留空，已有明确图纸需求时不强制填写研究问题。

每次输入先区分：明确的新增/删除/修改指令、目的陈述、范围/时间、分析参数、风格、交付格式。

- 明确指令更新草案，并显示具体变更。
- 问题描述触发候选图纸和理由；推导出的新增图先作为建议，不默认为用户选中。
- 同一图类同一参数合并；要求不同范围、起点、情景时建立独立实例，必要时允许比较图或多图布局。
- 系统推荐被拒绝后保留拒绝状态；没有新理由时不重复推荐。
- 只有会改变成果含义、且不能从上下文确定的歧义才追问；专业术语提供简短说明与小样。
- 如果用户选择的图不足以回答其问题，提示覆盖边界，但允许保留该选择。
- 可以直接从单张图进入，系统自动归组；不强制先选组，也不自动选中整组。
- 仅启用有已选图纸的组级任务卡；未采纳的推荐仍在候选区。跨组辅助计算不自动增加交付组。

例：用户选“道路”和“绿水”，再描述“研究北侧入口步行便利，最多3张”。系统保留两张，推荐“可达性分析”；若用户采纳，则确认3项；若用户拒绝，则保留两项及尚未覆盖的问题。

## 2. 需求字段分层

| 层 | 应记录的内容 | 何时需要 |
|---|---|---|
| 项目层 | 点位/红线、坐标、图纸北向、项目名称 | 选图时可未知，数据检查和计算前必须落实 |
| 范围层 | 显示范围、指标统计范围、数据获取范围 | 编译分析任务时分别确定 |
| 组级任务卡层 | 本组已选图纸、兼容的共用设置、资料检查、表达和验收 | 选中本组图纸时展开；同一条件只填一次 |
| 图纸实例层 | 图类稳定ID、问题、分析模式、关键参数、情景 | 需求确认时至少明确影响方法的口径 |
| 数据层 | 来源、时段、范围、精度、单位、缺测、估算字段 | 计算前校验 |
| 表达层 | 视角、色板、线宽、图框、图例、纸张、语言 | 可先采用显示给用户的默认模板，预览时再调整 |
| 交付层 | 单图或展板、格式、可编辑部分、数量 | 批量出图前明确 |

每个参数记录value、来源（用户明确输入/用户采纳/默认建议）、单位和确认状态。示例中的数值均为演示，不自动成为真实项目参数。

不要给用户一次展示50张图的全部参数。按已选图类与模式展开需要的信息；底图分类图不索要风数据，覆盖率图不索要楼层，太阳轨迹不索要完整建筑模型。

组级共用设置只对适用图纸生效。逐图覆盖必须显示差异；某张图缺资料时保留具体缺项，不直接把整个组判为不可用。

## 3. 明确需求与数据可用分开

图纸实例分别保存需求状态、数据状态、运行状态。

需求状态：draft → proposed → selected → confirmed；rejected单独保留。用户直接明确要求某图可直接进入selected，不必经过推荐。

数据状态：not_checked / ready / needs_input / unavailable。数据不足时列出缺失项及其影响，不能默认为真实零值。

运行状态：not_implemented / not_started / running / computed / rendered / needs_review / complete / failed。当前四类基础适配器可运行，其余图类仍为not_implemented；以执行器能力注册表和运行清单为准，不以研究目录的历史快照判断现有能力。

数据不足时，用户可补资料、明确接受某种估算/示意、替换图类或跳过。影响分析口径的替换要回显并让用户采纳。风流模拟不能悄悄换成几何流线，路网分析不能悄悄改成直线圆。

## 4. 一份数据怎样支持全部图类

位置与红线 → 基础地物 → 派生数据 → 分析结果 → 图形表达 → 版面 → 导出与记录。

基础地物保留原始数据；按用途生成分析几何、可通行路网、地面高程、建筑体块、气象时间序列、照片和现场约束。它们可以被多张图共用。

派生任务按依赖图运行。组合图调用既有分析成果，不因为它用到了道路，就自动多交付一张未选中的道路图。辅助计算数、研究模块数、图纸实例数和导出文件数分别统计。

例如：一个“南北入口比较”研究，可以有两个路网计算实例、一张双栏比较图，以及SVG/PNG/PDF三个导出文件。

## 5. 三种空间范围

- 显示范围：图纸画到哪里。
- 分析范围：指标的统计分母、路网成本或模型研究范围。
- 数据获取范围：为计算所需的外扩数据范围。

例：步速1.2m/s、15分钟，对应1080m的沿路成本上限。若显示圈仅600m，也不能直接把路网裁到600m再计算完整15分钟服务范围；应扩展网络并检查可达前沿是否接触数据边缘。统计背景和输出视窗可以另行裁切。

同理，风场边界、噪声外部声源和地形汇流也可能要求外扩范围。

## 6. 参数变化如何重算

- 仅改颜色、字体或版式：复用已有指标并重绘。
- 改统计网格、起点、步速或日期：重算受影响的分析，再更新依赖的图纸和展板。
- 改底图或数据时段：更新对应数据版本并重新检查下游结果。
- 已确认清单改变时显示差异；保留无关图纸的确认状态，避免整单重复填写。

## 7. 统一出图约定

真实数据几何与用于排版的简化几何分开保存。标题、图例、比例尺、真北、单位、时段、来源、方法及估算标记随图导出。

规划输出：SVG、PNG、PDF；SVG中的照片或模拟栅格可能是嵌入图像，应标明哪些部分可编辑。3D模型等额外交付另建导出模块，不能把能画轴测图等同于已实现3DM导出。

## 8. 每张图的验收与全套成果验收

逐图验收采用catalog/diagrams.json中的proposed_acceptance。

全套成果必须另外检查：

1. 坐标对齐、裁切、比例、真北、日期与主题一致。
2. 数字与分类来自同一版本的统计结果；不同统计对象或范围在图上说明。
3. 辅助计算和用户选定的交付清单一一对应，未完成的图单列原因。
4. 估算、示意、模拟和观测有明确标记。
5. 保存可复现的项目配置、数据版本/哈希、算法版本和修改记录。
6. 对模拟、路网及高程算法先用可检验的简单基准验证，再用于真实项目。

## 9. 按依赖实现的顺序

先建立稳定图类目录、任务配置、基础数据容器、样式及导出骨架。用四类免费基础图对应的独立实现验证数据到成图的闭环。

再逐组补齐几何统计、路网、高程、气象、三维、组合展板，最后落实需要更多模型和校验的环境模拟与设计解读。

这是逐步完成全目录的开发路径；目录可列出规划能力，但界面必须区分已实现和待开发。
