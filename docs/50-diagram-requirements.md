## 一项任务要明确什么

项目共用：位置/红线、显示范围、分析范围、数据获取范围、坐标/单位、数据时段、样式、纸张与导出要求。三种范围分别保存；例如15分钟路网分析可能需要比600米显示圈更大的网络。

每张图记录：稳定图类ID、要回答的问题（可空）、分析口径/模式、关键参数、数据依赖、表达方式、允许的估算、来源、验收规则。网站序号只作目录索引，不能充当稳定ID。

这些逐图字段由组级任务卡、项目共用信息和选图后的必要参数共同填充，避免每张图重复索要相同条件。

使用者可以同时选图和描述问题；明确的增删改指令更新任务，系统推导出的新增图先作为建议。确认需求与确认数据足够是两个状态。已选图没有数据时列出缺项，未经用户采纳不擅自改成另一种分析。

## 逐图规格

“数据”列出基础依赖；条件依赖只有在对应模式被选择后才提出。未填写的字段保持未知，不把推荐默认值冒充已确认输入。

### 01 轴测放大分析图 / Axonometric Callouts

- 图类ID：`axocallout`。App显示名称：Axonometric Callouts。
- 要回答的问题：怎样用轴测与放大节点讲清重点？
- 需要确认：放大对象；放大窗口数量；体块精度和布局。
- 基础数据：建筑轮廓、建筑高度、楼层或楼面面积、道路与路网、项目点位与红线。
- 建议计算：复用体块模型 → 选取重点对象 → 为窗口与总图建立关联。
- 出图过程：主轴测图、圆形细节窗和编号引线。
- 建议工具：空间分析结果、SVG、排版模板、人工标注。
- 验收：放大窗对象能回到总图；比例变化明确；标签不遮挡。
- 解读边界：主要是已有结果的组合表达；不自动增加分析结论。

### 02 场地圆形分析拼图 / Site Inset Board

- 图类ID：`insetboard`。App显示名称：Site Inset Board。
- 要回答的问题：如何用一个主图和若干小图讲清场地？
- 需要确认：主图范围；四个小图内容；统一或分别使用比例尺。
- 基础数据：项目点位与红线。
- 条件数据：当选择某个子图时，需要所选子图实际依赖。按子图实际依赖展开，不无条件索要全部资料。
- 建议计算：读取已计算图层 → 构建主图与四个分析视窗 → 自动布局。
- 出图过程：重点主图与四个圆形小图、统一图例和编号。
- 建议工具：空间分析结果、SVG、排版模板、人工标注。
- 验收：每个小图内容有来源；各视窗比例尺分别正确；同一位置保持对齐。
- 解读边界：它依赖所选子图的数据；无法生成的子图应明确缺失或由用户替换。

### 03 功能分区总图 / Zoning Plan

- 图类ID：`zoningplan`。App显示名称：Zoning Plan。
- 要回答的问题：需要表达现状功能，还是提出方案功能分区？
- 需要确认：现状/规划法定/拟建方案；分区边界与面积要求；路径和标签。
- 模式：现状功能总图；经确认的拟建功能分区。
- 基础数据：项目点位与红线。
- 条件数据：当现状功能时，需要现状用地/功能面。
- 条件数据：当方案分区时，需要拟建功能分区或需求。可以人工输入，或在目标和约束明确后提出草案，由用户确认。
- 建议计算：现状模式复用属性面 → 方案模式读取或经确认生成分区 → 核对分区面积与冲突。
- 出图过程：渐变或分类分区、路径、编号和功能标签。
- 建议工具：空间分析结果、SVG、排版模板、人工标注。
- 验收：现状与方案标签明确；分区拓扑和面积可核对；方案内容经过使用者确认。
- 解读边界：不能把自动提出的功能分区包装成现状事实或法定规划。

### 04 视线分析 / Visual Analysis

- 图类ID：`viewcones`。App显示名称：Visual Analysis。
- 要回答的问题：从哪些真实位置能够看见场地，照片如何对应？
- 需要确认：观察目标；视点数量与高度；真实照片或几何视域；照片朝向和时间。
- 模式：真实街景照片与编号视锥展板。
- 基础数据：带位置朝向的真实街景照片、建筑轮廓、建筑高度、楼层或楼面面积、项目点位与红线。
- 建议计算：获取有位置和相机信息的照片 → 计算视锥及遮挡 → 照片投影或人工复核场地标注。
- 出图过程：平面编号视锥、照片面板、目标强调与摄影者署名。
- 建议工具：空间索引、数值计算、射线遮挡、专门的二维LBM实现、SVG/栅格渲染。
- 验收：照片与视点编号对应；无照片时不生成虚构街景；目标高亮位置经过核对。
- 解读边界：这是带照片的视觉展板；与Deep Analysis的单点视域/VGA指标并不等同。

### 05 线稿轴测 / Line Axonometric

- 图类ID：`lineaxo`。App显示名称：Line Axonometric。
- 要回答的问题：怎样用干净的线稿轴测表达场地？
- 需要确认：轴测角度；重点场地；隐藏线或透视线策略。
- 基础数据：建筑轮廓、建筑高度、楼层或楼面面积、道路与路网。
- 建议计算：生成体块 → 提取边线并投影 → 进行隐藏线处理与图形简化。
- 出图过程：线稿底景与重点区域强调色，必要时叠加道路。
- 建议工具：Three.js、地理坐标转换、SVG。
- 验收：主要边线连续；隐藏线策略一致；重点范围准确落位。
- 解读边界：网站称平面斜轴测；我们需明确具体投影而不是按名称混用透视。

### 06 中心可达性图 / Central & Accessible

- 图类ID：`radialnet`。App显示名称：Central & Accessible。
- 要回答的问题：如何突出场地与周边目的地的中心联系？
- 需要确认：目的地选择；放射直线或真实路线；等高线或距离圈的含义。
- 基础数据：项目点位与红线、设施点与属性。
- 条件数据：当显示真实路线时，需要道路与路网、步行通行限制、入口及开放条件。
- 条件数据：当显示等高线时，需要地面高程DEM/DTM。
- 建议计算：按明确规则选择目的地 → 生成放射联系或复用路网结果 → 按需叠加地形。
- 出图过程：场地居中、目的地放射连接及背景层。
- 建议工具：空间分析结果、SVG、排版模板、人工标注。
- 验收：每条联系有真实目的地；直线连线不标真实步行路线；等高线必须来自高程数据。
- 解读边界：菜单说明是组合图；不默认它计算了接近中心性、介数或空间句法。

### 07 机遇与限制分析 / Opportunities & Constraints

- 图类ID：`oppcon`。App显示名称：Opportunities & Constraints。
- 要回答的问题：哪些事实构成设计机会或限制，为什么？

- 图类ID：`sunaxo`。App显示名称：Sun & Wind Axonometric。
- 要回答的问题：太阳轨迹、受光立面与主导风怎样在同一轴测图表达？
- 需要确认：季节和时刻；立面受光判定方式；风统计时段与相机。
- 基础数据：建筑轮廓、建筑高度、楼层或楼面面积、日期、时间与时区、风向风速时间序列。
- 建议计算：生成体块与太阳轨迹 → 按法向和遮挡判定瞬时向阳面 → 叠加统计主导风。
- 出图过程：轴测体块、季节太阳弧、受光面与主导风箭头。
- 建议工具：Three.js、地理坐标转换、SVG。
- 验收：与太阳轨迹图共享天文参数；风向来向去向清楚；瞬时受光不标作累计日照。
- 解读边界：当前目录已替换旧日长项；向阳立面、累计日照和风速模拟需分别说明。

### 50 太阳辐射 / Solar Radiation

- 图类ID：`climsolar`。App显示名称：Solar Radiation。
- 要回答的问题：区域短波太阳辐射全年如何变化？
- 需要确认：统计期；MJ/m²·day或其他单位；月均每日总量或月累计。
- 模式：月均每日短波辐射；月累计短波辐射。
- 基础数据：短波辐射时间序列。
- 建议计算：获取短波辐射记录 → 进行量纲换算 → 按明确时间尺度汇总。
- 出图过程：月辐射曲线或柱状图，标注数据网格和单位。
- 建议工具：气象数据接口、pandas、pvlib、SVG。
- 验收：日均与月累计不混用；数值可追溯到原数据；区域尺度明确。
- 解读边界：本目录图是气候短波辐射统计；场地遮挡后地表辐射属于另一个计算任务。

## 共同验收

1. 同一项目的图题、图例、汇总栏、统计表采用一致或明确标注不同的统计口径。
2. 原始分析几何与用于表达的简化几何分开保存，图形概化不改变面积指标。
3. 无资料标记为“数据不足/未知”，不自动填0、不编造节点、高度、街景或测量值。
4. 真正的路网结果要能回到逐边成本；直线圈必须明确其距离假设。
5. 模拟结果保存边界、网格、求解状态、单位与参数；未收敛不能标记为完成。
6. SVG用于可编辑线面与文本；街景、热力或模拟栅格允许嵌入，但注明可编辑部分。
7. 比例尺、真北、单位、数据来源、统计期、方法及估算标识应随成果导出。
8. 保存项目配置、数据版本/哈希、方法版本及图纸修改记录；样式调整优先重绘，分析参数变化才重算受影响结果。
