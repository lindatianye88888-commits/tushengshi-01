# 图省事 01：从4类到50类的开发计划

计划日期：2026-10-25。基线为v0.2：通用执行流程已跑通，4类基础图可运行，另外46类为待开发规格。这里的目标是把全部50类做成有明确方法、真实数据和验收记录的可执行能力。

## 开发思路

以共用的数据和计算能力为主线开发。已有建筑、道路和用地先支持空间统计；随后增加设施点、真实通行网络、高程栅格、气象时间序列和建筑高度。组合图读取已经完成的分析结果。每一类保留自己的方法和输出，不靠换标题、换颜色重复计数。

图类存在、代码实现、数据齐备、真实案例验证分别记录。一个图类可以先完成一个明确模式，例如建筑密度先做“建筑轮廓覆盖率”，容积率在楼层资料及其验证接通后另行宣布。目录中的全部可选参数不会因为一个模式已实现就自动变成可用。

开发批次按依赖排列，与现有八组任务卡是两个维度。机器可读排期见 [development-plan.json](../catalog/development-plan.json)；当前真实能力以 `python -m workflow catalog --json` 为准。

## 第一批怎么做

### 建筑密度 `density`

- 第一模式：米制投影上的规则网格建筑轮廓覆盖率。
- 分子：建筑面先在统计范围内裁剪并取并集，避免重叠重复计算。
- 分母：每个网格与分析范围相交后的有效面积，边界小格不使用完整方格面积。
- 图面：连续空间网格按固定密度等级着色；输出整体覆盖率及逐格统计。
- 核验：重叠建筑、边界裁剪、空格、排除对象、网格面积与建筑面积守恒。当前轮廓含遥感屋顶投影，指标名称保留“轮廓覆盖率”。

### 街道方向玫瑰图 `orientrose`

- 第一模式：真实北向、按中心线线段长度加权的方向统计。
- 对道路线逐折点拆段，不能用整条弯曲道路的首尾连线代替方向。
- 按层级区分后合并重复线；支持明确选择是否计入步道、是否合并相反方向。
- 核验：东西/南北线的已知方向、弯道、反向顶点顺序、重复线、立交层级和各扇区长度合计。
- 当前计算不生成路网通行图，不将方向图解释为可达性。

### 建筑类型学图录 `typology`

- 第一模式：完整位于分析范围、满足最小面积的建筑轮廓，按面积降序选取有限数量，保持相同比例尺展示。
- 保留来源ID、原始坐标、面积、周长与形状紧凑度；图录卡片可追溯到输入对象。
- 核验：孔洞与多部件、相同轮廓去重、稳定排序、选取数量、原始轮廓保真与统一比例。
- 图录表达几何形态，不从外形推断年代、用途、结构或建筑风格。

## 共用执行器需要补齐什么

1. **适配器注册**：每类登记已支持模式、参数约束、依赖、算法和渲染版本，未支持的模式明确报缺项。
2. **多种资料**：除现有线面GeoJSON，增加POI点、路网连接、栅格、时间序列和三维高度；每种资料保留来源、时段、坐标、哈希和缺失说明。
3. **多资源计算**：现有执行器主要读取一份输入；组合与网络类改为按资源映射传入、按所有依赖哈希缓存，冻结和完整性检查同步扩展。
4. **多种图面**：地图、统计图、轮廓图录、三维投影和组合版分别绘制；共用中文图框、图例、数据表、方法说明与来源署名。
5. **指标合同**：面积、长度、计数、分布与无量纲指标分别定义统计合计，不能把所有输出都当面积覆盖率验收。
6. **真实跨端验收**：Codex先完成本地算例和成都案例；WorkBuddy用干净下载的同一版本复跑并记录环境与结果。只有测试过的客户端列为实测，不把文件协议兼容写成安装完成。

## 数据接入顺序

- 建筑、道路、用地、绿水：复用当前版本化Overture资料及本地导入。
- POI/站点/边界：增加对应公开数据适配器及人工导入，不把公开数据未收录当成现实不存在。
- 通行网络：保留Overture segments/connectors及限制语义，按共享连接点构网；单纯几何相交不构成真实连通。[官方连接模型](https://docs.overturemaps.org/guides/transportation/segments-and-connectors/)、[道路限制](https://docs.overturemaps.org/guides/transportation/roads/)。
- 高程：优先支持用户可靠DTM；公共全球数据需说明分辨率和表面性质。Copernicus DEM是包含建筑和植被的DSM，不能直接称裸地地形。[官方说明](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)。
- 气象：计划接入NASA POWER等有明确统计期和单位的数据，并支持本地时间序列。年内实测/再分析与多年气候平均分开选取。[NASA POWER API](https://power.larc.nasa.gov/api/pages/)、[气候平均接口](https://power.larc.nasa.gov/docs/services/api/temporal/climatology/)。
- 高度、声源、风和现场条件：资料不足时保留缺项；需要估算时由任务明确模式、参数与用途边界。

## 每一类怎样才算完成

每类至少交付：实际计算模块、图面模块、明确参数与数据校验、可手算或可比对的自动算例、成都或适用真实场地成果、SVG/PNG与数据表、方法和来源说明、重绘/打包/干净目录复跑检查。PDF沿用矢量导出能力，新增特殊图面在其宣称可用前另做版面核对。

“代码写了”还不能直接记为真实案例验收通过。算例失败、图面遮挡、统计不一致、缺少数据来源或断开原资料后不能按约定复跑，都必须解决后再计入该批交付。

每批在GitHub提交代码、更新可运行数量及支持模式，附实际验证记录。历史研究目录保留原有观察时点；README、运行命令和开发排期反映最新能力，避免规格清单与执行状态混用。
